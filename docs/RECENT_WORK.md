## 今回の目的

ユーザーから「`recover_proba`の符号が逆（$e^{+\ell_k}$ を使っているが $e^{-\ell_k}$ が正しい）」との指摘を受け、修正・再検証する。前回報告した「Group LassoのHellinger忠実性が悪い」という結論はこのバグの影響を受けている可能性が高い。

## 実施した変更と主要な変更ファイル

1. **`src/grouplasso.py`**: `recover_proba`のバグを修正。$\ell_k=\log(p_r/p_k)$ の定義に対し、正しい逆変換は $p_k=p_r\cdot e^{-\ell_k}$、$p_r=1/(1+\sum_k e^{-\ell_k})$ である（$p_r+\sum_k p_k=1$ から導出）。修正前は符号を反転した $e^{+\ell_k}$ を使っており、$\ell_k$ が大きい（＝参照クラス$r$が優勢な）ときほど確率推定が大きく誤る実装になっていた。

## 重要な判断とその理由（★今回一番重要、前回の結論を覆す訂正）

**指摘は完全に正しかった。前回の「Group Lassoは構造共有と引き換えに絶対確率忠実性を犠牲にする」という結論は、実質的にバグによる人工的な結果だった。**

修正前後のHellinger忠実性（全体平均、値が小さいほど良い）：

| | 修正前（バグあり） | 修正後 |
|---|---|---|
| Group Lasso | 0.402（one-vs-restの24倍悪い） | **0.0173（one-vs-restとほぼ同等）** |
| one-vs-rest（参考） | 0.0169 | 0.0169（変化なし） |
| Fisher（参考） | 0.0588 | 0.0588（変化なし） |

修正後は、**Group Lassoが4指標すべてでone-vs-rest以上**という結果になった。

```
                  ovr        fisher      grouplasso
Hellinger忠実性   0.0169       0.0588       0.0173   （ほぼ同点、Fisherより3.4倍良い）
符号一致率        0.7994       0.7910       0.7999   （最良）
stability(正規化) 0.0467       0.1174       0.0461   （最良）
feature overlap   0.458        0.518        1.000    （圧倒的最良、構造的に保証）
```

前回セッションで立てた「Fisherと同じパターン（構造共有は絶対確率忠実性を犠牲にする）が2例目として確認された」という一般化は**撤回する**。実際には、Group Lassoの絶対確率忠実性の悪さはバグの産物であり、正しく実装すればトレードオフなしでone-vs-restを上回る。この一般化した主張は根拠を失ったため、修論の記述に反映しないよう注意が必要。

なお、この経緯自体（実装バグが結論を左右しうること、符号のような基本的な部分でも実測結果を鵜呑みにせず検算が必要なこと）は、方法論的な教訓として記録に値する。
